### Задание 2. Настройка шардирования mongo-db

В данном задании я релизовал шардирование mongo-db

## Описание docker-compose
В докер-компоуз файле я завел: 
1) configSrv - контейнер для хранения конфигов mongo. Он хранит информацию о нодах, распределении чанков по шардам. К нему обращается ноды и роутер. Конфиг-сервер должен быть HA, поэтом обязательно надо добавлять его в replicaSet. В этом задании в replicaSet только одна нода для простоты конфигурации.
2) shard1, shard2 - ноды монги для шардирования. Каждая из нод находится в своем replicaSet аналогично configSrv\
3) mongos_router - роутер, который маршрутизирует пользовательские запросы по шардам.
4) mongo_init_replicas и mongo_init_cluster - инит контейнеры для настройки кластера.

## Процесс настройки кластера
Процесс запуска кластера состоит из 4 этапов:
1) Запуск контейнеров configSrv, shard1, shard2
2) Запуск mongo_init_replicas
   Этот контейнер выполняет скрипты из папки init-replicas. В них инициализируются реплика сеты для конфиг-сервера и шардов. После этого роутер сможет получать данные от этих нод
3) Запуск роутера. На самом деле роутер запускается вместе с mongo_init_replicas, но успешно отрабатывает только после выполнения mongo_init_replicas
4) Запуск mongo_init_cluster
   Этот контейнер выполняет скрипты из папки configure-cluster. В рамках этого скрипты в базе регистрируются шарды и включается шардирование по хешу для коллекции users по полю _id.

## Проверка настройки
После завершения конфигурации выполняется команда scripts/mongo-insert-users.sh  
Эта команда добавляет в базу 1000 пользователей в коллекцию users.
Команды scripts/mongo-check-shard1.sh  и scripts/mongo-check-shard2.sh отображают распределение пользователей по шардам
